## Goal
1) Unblock the build (independent of the unification).
2) Merge platform sign-in into `/auth` with a smart flow: no company code → platform; with company code → tenant.

## Part 1 — Build fixes (must land first)

- **`src/routeTree.gen.ts`**: current file is a hand-compressed stub with `@ts-nocheck`, which erases all `to="/…"` and `createFileRoute("/…")` types (that's why the ~40 TS2322/TS2345 errors all say the target type is `undefined` or `"." | ".."`). Delete the file so the TanStack router plugin regenerates a full typed tree on the next dev/build run.
- **`src/routes/sitemap[.]xml.ts`**: uses a `server:` block inside `createFileRoute`, which isn't valid here and crashes the plugin with "Crawling result not available" (this is the root cause of the whole build failure). Move it to `src/routes/api/public/sitemap[.]xml.ts` using the documented `server: { handlers: { GET } }` shape for API routes.
- **`src/routes/scan.tsx:809`**: change the offending `string | null` prop to `value ?? undefined` (single-line adjustment, no logic change).

Expected outcome: `bun run build:dev` and `tsgo` pass; all "not assignable to `"." | ".."`" and "not assignable to `undefined`" errors disappear together because they share the same root cause (missing route tree types).

## Part 2 — Unified sign-in on `/auth`

Single form on `/auth` with three visible fields: البريد الإلكتروني، كلمة المرور، كود الشركة (اختياري).

Submit logic:
```text
if companyCode is empty:
    signInWithPassword → get_my_platform_profile
        if profile exists → navigate /platform
        else → signOut + error "الحساب غير مخول للدخول بدون كود شركة"
else:
    resolve_login_organization(code)
    signInWithPassword → activateOrganization
        → navigate /admin or /cashier by role
```

Field-level notes:
- Field order stays RTL-friendly; كود الشركة يظهر بنص توضيحي: «اتركه فارغًا إذا كنت من فريق KOB».
- خطأ موحّد بصياغة عربية واحدة (لا خلط لغات).
- On success we clear the other context (`clearOrganization()` on platform path, `platform.refresh()` on tenant path) so state stays consistent.

Redirect side of the change:
- `PlatformAuthPage` component keeps existing behavior but the route file `src/routes/platform-auth.tsx` redirects to `/auth` (via `beforeLoad: () => redirect({ to: "/auth" })`) so old links/bookmarks keep working.
- `RoleGate`, `PlatformGate`, and other places that navigate to `/platform-auth` are updated to point to `/auth`.
